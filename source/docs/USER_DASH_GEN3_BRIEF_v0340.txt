=========================================================
PASS GOAL
POKÉMON DASH — AUTHENTIC GEN 3 COURSE / ASSET OVERHAUL
=========================================================

Pokémon Dash currently has a working racing-game foundation, but visually it still feels like a prototype assembled from painted backgrounds, floating sprites and placeholder assets.

This pass is NOT about simply adding more decoration.

Rebuild the race-course presentation so it looks like a genuine Pokémon Gen 3-era minigame using authentic or faithfully reconstructed Gen 3 assets and visual language wherever practical.

The intended quality bar is:

"If Game Freak had made a small Pokémon racing minigame inside Ruby/Sapphire/Emerald, this could plausibly be what it looked like."

The game should still fit LuckyDex's existing UI, but the actual race environment should strongly resemble a coherent GBA Pokémon game rather than a modern painted road.

=========================================================
1. AUDIT FIRST — DO NOT START BY DRAWING MORE PLACEHOLDERS
=========================================================

Before changing anything:

1. Inspect the complete Pokémon Dash implementation.
2. Inspect every Dash-specific asset.
3. Inspect all existing LuckyDex Gen 3 assets that can be reused.
4. Inspect authentic-v0200 assets and other Arcade asset folders.
5. Inspect any Emerald/Ruby/Sapphire tilesets already bundled.
6. Identify which current Dash visuals are:
   - authentic Gen 3 assets
   - reconstructed from authentic assets
   - generated/painted placeholders
   - simple coloured geometry
   - badly cropped/incomplete sprites
   - visually inconsistent assets
7. Trace how:
   - course rendering works
   - preview images are produced
   - scenery is positioned
   - world scrolling works
   - boost pads / berries / hazards render
   - Pokémon sprites scale and animate

Write a concise findings note before implementing.

Do not blindly preserve bad assumptions from the current renderer.

2. STOP USING "PAINTED ROAD" COURSE BACKGROUNDS
=========================================================

The current race course looks like a single painted/generated image with objects placed over it.

This is not the desired direction.

The course should instead be composed from:

- Gen 3 tiles
- metatiles
- environmental sprites
- route objects
- gym assets
- cave assets
- trees
- water
- cliffs
- fences
- flowers
- grass
- bridges
- machinery
- rocks
- building/interior tiles
- other appropriate Gen 3 scenery

The road, verge and scenery should look like a coherent place constructed from Pokémon game assets.

Do not just paste random sprites onto the current image.

It should look like an actual location.

A course does not need to correspond exactly to an existing Pokémon route.

It can be an original race course assembled from genuine Gen 3 visual building blocks.

That is preferable to a fake "route screenshot".

=========================================================
5. PIXEL ART RULES
=========================================================

All race-environment artwork must remain pixel clean.

Use:

- nearest-neighbour scaling
- integer-friendly placement where practical
- no image smoothing
- no anti-aliased scaling
- no blurry CSS transforms
- no soft modern gradients over pixel scenery
- no painted backgrounds

Avoid mixing:
- tiny GBA sprites
- high-resolution painted art
- CSS rectangles
- differently scaled sprites

in the same scene.

If a new LuckyDex-specific asset must be created, match Gen 3 constraints rather than merely applying a pixel-art filter.

=========================================================
7. WORLD-SPACE / SCROLLING MODEL
=========================================================

The sides/verges currently move at a different apparent speed from the road, which makes them look like a distant background layer below the road.

This is wrong.

The road and immediate roadside scenery occupy the SAME physical world plane.

Trees, rocks, grass, barriers and nearby course objects should therefore progress toward the player consistently with the road.

Do not use arbitrary parallax on nearby scenery.

Parallax may only be used for genuinely distant background layers.

The visual world should make spatial sense.

15. POKÉMON PRESENTATION
=========================================================

Do not introduce violent sprite shaking again.

Pokémon should feel alive, but movement must remain readable.

Audit the current motion system.

Desired movement:

GROUNDED:
- small gentle running bob
- slight forward lean while sprinting
- slight lateral lean while steering

FLYING / LEVITATING:
- smooth hover
- very small vertical oscillation

SERPENTINE:
- subtle glide/sway

COLLISION:
- brief impact motion
- quick recovery

BOOST:
- brief stronger forward/scale response

Avoid constant high-frequency vibration.

Keep sprites pixel-clean.

Preserve sensible species-scale normalisation.

Large species should feel larger without covering half the road.

=========================================================
