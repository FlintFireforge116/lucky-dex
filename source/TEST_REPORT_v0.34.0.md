# LuckyDex v0.34.0 — Pokémon Dash Emerald overhaul

Baseline: supplied `LuckyDex_source.zip`, verified as v0.33.1 /331. Release: **0.34.0 /340**, application ID **com.example.luckydex**. Original development signer preserved, supporting in-place updates.

## Delivered changes

All 18 Type League courses use data-driven environments assembled from native Pokémon Emerald floors, metatiles, complete environmental objects and animation frames. Normal/Grass/Bug/Fairy use route and vegetation composition; Water/Flying use bridges and shore/open-route scenery; Fire uses volcanic cave/ash/lava; Ground/Rock/Dragon use desert, cave and ancient stone; Poison uses marsh/rough-ground vegetation; Ice uses frozen floors and rocks; Fighting/Psychic use gym interiors; Electric/Steel use machinery and mechanical floors; Ghost/Dark use Mt. Pyre and darker cave/interior assets. Shared section systems preserve comparable race geometry while environment families and landmarks differ.

The new catalog contains **59 authentic or source-reassembled Emerald PNGs**. It decodes both primary and secondary tile banks, original palette indices, actual map rectangles and native field-effect grass. Complete trees, machinery and columns have bounded base anchors and footprints. The Oran Berry is an exact visible crop of Emerald's item icon. Yellow/red north-facing Mossdeep Gym floor pads replace generated boost arrows; their response as boost states is a LuckyDex interpretation. Full per-asset provenance and classifications are in `docs/DASH_GEN3_ASSETS.md` and the runtime manifest. **204 checksum-listed source files** support offline regeneration; redundant upstream downloads are excluded from the ZIP.

Eight reusable sections provide open straights, chicanes, boost halls, bridges, squeezes, recovery meadows, landmarks and finishes. Seeded variation preserves safe hazard spacing, avoids three-lane walls and keeps scenery RNG separate. Terrain, scenery, objects and racers now share the **3.05 px/world-unit** projection. Canvas caching, nearest-neighbour blits, a consistent 3× environment pixel scale and depth ordering replace inconsistent scroll/scaling assumptions. Scenery stays inside horizontal world bounds; objects naturally enter/leave vertically as the world scrolls.

Previews for all 18 courses are real seeded frames produced by the playable renderer, rather than separate promotional scenes. Compact menus use those previews and native route textures. Held left/right starts movement on press, permits continuous corrections, and stops on release/cancel; sprint and legacy target-lane APIs remain supported. Grounded, hovering and serpentine motion is gentle. Berry disappearance, pickup flashes, pad response and collision zones correspond to visible native footprints.

One body-mounted, VisualViewport-aware Dash shell owns HUD/course/controls and restores its original Arcade slot on exit. At 360×640, 360×740, 390×844 and 412×915, the course receives 77–83% of viewport height, controls remain visible, and there is no page scrolling. The supplied v0.33.1 Chrome baseline already fit these sizes; the reported Android clipping was **not reproduced** here. Portal ownership prevents transformed app ancestors from controlling Dash placement.

## Intentional limits

Native Android device/WebView execution and heap profiling remain unverified: ADB could not establish a daemon/device connection in this environment. Chrome mobile tests and APK build/payload/signature checks passed. Historical failures above remain outside this Dash pass. Existing actor sprites and save/currency systems are retained; no weapons, drifting, joystick or unrelated minigame redesign was introduced. Retired generated Dash art remains in the source for historical provenance, but the active course renderer uses the new catalog.

An optional redundant-cache deletion was rejected by automatic approval review because retention paths were inconsistent. Those files were retained locally; the release ZIP includes only the checksum-listed rebuild inputs. No requested deliverable is blocked by that cleanup decision.
